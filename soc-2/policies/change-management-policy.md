# Change Management Policy

**Document ID:** SOC2-POL-004  
**Version:** 0.1  
**Status:** Draft — Portfolio Example  
**Policy Owner:** IT Operations  
**Review Frequency:** Annually and after significant changes

## 1. Purpose and scope

Establish a controlled process for changes to in-scope systems, infrastructure, configurations, applications, and security controls.

## 2. Requirements

- Changes must be logged with purpose, scope, risk, impact, owner, and proposed implementation window.
- An authorized person independent of the implementer should approve changes where feasible.
- Changes must be tested in a suitable environment and results recorded before production deployment, unless an approved emergency process applies.
- Production changes must include implementation and rollback plans, and be validated after deployment.
- Emergency changes must be documented promptly, reviewed after implementation, and approved according to defined authority.
- Access to change tools must be restricted and reviewed.
- Unauthorized changes and failed changes must be investigated and tracked to resolution.
- Change records must be retained according to documented retention requirements.

## 3. Roles and review

Change requester, approver, implementer, system owner, and reviewer responsibilities must be assigned. Review the policy annually and after significant change.
